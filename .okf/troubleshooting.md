# Troubleshooting by Symptom

No code exists yet. These rows are risks the design already knows about; replace them with real symptoms as they appear.

| Symptom | Likely cause | See |
|---|---|---|
| Notification says a message is encrypted instead of showing its text | The extension could not open the shared store or ran out of time | [ADR 0007](../docs/adr/0007-shared-session-store-app-group.md), [ADR 0009](../docs/adr/0009-push-gateway-and-nse-decryption.md) |
| Sign-in fails with "server not supported" | The homeserver has no sliding sync | [ADR 0003](../docs/adr/0003-matrix-rust-sdk.md) |
| A screen looks wrong on iOS 18 only | A version difference was written outside `DesignSystem` | [Design System](architecture/components/design-system.md) |
| After updating from the Flutter app, the user is asked to sign in and old messages are unreadable | Expected: a new device is created; the user must enter the recovery key | [ADR 0012](../docs/adr/0012-reuse-flutter-bundle-identifier.md) |
| Sign-in succeeds on the server (the crypto store is created) but `login` never returns | The SDK platform was not set up: `MatrixPlatform.setUp()` must run before any client is built | [Data Layer](architecture/components/data.md) |
| A feature package does not compile after importing the SDK | Only `MatrixData` may import it | [ADR 0006](../docs/adr/0006-sdk-behind-proxy-protocols.md) |
| Messages from Flutter or web senders stay unreadable on a new device ("Verify this device with your recovery key to read it.") | The sender withheld the key because this device was not cross-signed (`withheldForUnverifiedOrInsecureDevice`): twake-on-matrix shares keys only with verified devices. The unlock with the ToM key verifies the device; older keys then come from the backup if the sender uploaded them. Once verified, the help says the sender did not share the key | [ADR 0024](../docs/adr/0024-recovery-key-kept-by-tom.md) |
| A message or a chat list row stays "encrypted" although the notification showed its text | The extension stored the room key in the shared store. The SDK's event cache re-decrypts on its own only for keys received in the same process (`event_cache/redecryptor.rs` in the pinned SDK), so the app asks again: the open chat and the rows still encrypted, when the app becomes active, when a push arrives in the foreground and after the unlock with the ToM key. In SDK 26.04.01 `Timeline.retryDecryption` ignores its session ids and retries every undecryptable item of that timeline | [ADR 0007](../docs/adr/0007-shared-session-store-app-group.md), [ADR 0024](../docs/adr/0024-recovery-key-kept-by-tom.md) |
| The app closes at once when a notification is tapped while it is not running (crash report: `NSAssertionHandler` in `-[UIApplication _performBlockAfterCATransactionCommitSynchronizes:]` under `AppDelegate.userNotificationCenter(_:didReceive:)`) | A `nonisolated async` notification delegate method returns on a background executor, so UIKit gets its completion off the main thread and asserts. The delegate methods are main-actor isolated (`@preconcurrency UNUserNotificationCenterDelegate`). `scripts/e2e.sh cold-start` replays the tap on the simulator ([#84](https://github.com/nqhhdev/twake-chat-ios/issues/84)) | [ADR 0009](../docs/adr/0009-push-gateway-and-nse-decryption.md) |
| A chat opened from a notification after a cold start shows "Could not open this chat.", a spinner or no messages | The room joined while the app was dead is not in the app's store yet. `ClientProxy.room(id:)` waits for the room list, then the room's remote echo, within 10 s; `TimelineProxy.open()` gives up after 15 s and the room screen retries `roomNotFound` and `unavailable` ([#84](https://github.com/nqhhdev/twake-chat-ios/issues/84)) | [ADR 0009](../docs/adr/0009-push-gateway-and-nse-decryption.md) |
| Staging integration tests stall at sign-in until their time limit | Staging rate-limits logins per account (`429 M_LIMIT_EXCEEDED`, a retry after about 5 minutes); parallel runs on the one test account hit it. Run them alone, or against the local Synapse (`scripts/e2e.sh up`) | [ADR 0020](../docs/adr/0020-opt-in-local-staging-integration-tests.md) |
| A chat fails to open ("Could not open this chat." or a spinner) while another process uses the store, and the log says `EventCacheError(LockingStorage(Unobtained(TimedOut)))` | The SDK's event cache lock is a lease in `matrix-sdk-event-cache.sqlite3` (`lease_locks`). A live client renews it every 50 ms for as long as it lives, even with its sync stopped. The SDK's `spin_lock` gives up after about 1.3 s, and then each call tries only once. So the app could not open a timeline while the extension was working on the same store. `TimelineProxy.open()` now retries every 250 ms within its 15 s limit, and the room screen retries `unavailable`. A client cannot be made to "die" inside one test process (it kept its lease after its repository was released), so cold start is tested with real processes: `scripts/e2e.sh cold-start` ([#118](https://github.com/nqhhdev/twake-chat-ios/issues/118)) | [ADR 0007](../docs/adr/0007-shared-session-store-app-group.md) |
